導入の目的 ＆ 絶対に守りたいコア機能

⚡

2画面リアルタイム同期

本アプリ最大の強みである「先生PCで操作したら、生徒スマホが0.01秒で変わる」通信（BroadcastChannel / Realtime）が壊れていないかを常に自動監視します。

🛡️

権限分離と誤操作防止

先生（Teacher）と生徒（Student）が互いの画面を不正操作できないよう、認証とロール制限（RLS）を完全に保護します。

🚀

開発スピード＆デグレ防止

今後の機能追加時に「昔作った機能が突然動かなくなる」事故を防ぎ、AIが自律修復しながら爆速で開発を継続できます。

2

技術方針（ここまで検討しています）

01

テストツール: Playwright（マルチコンテキスト対応）

Cypressでは難しい「1つのテストコード内で【先生PC画面】と【生徒スマホ画面】を同時に起動してリアルタイム同期を検証する」ことが標準で可能なため選定。

02

外部APIのモック化（Gemini AI・LINE通知）

AI診断やLINE通知などの外部通信はテスト時にモック（ダミー応答）に差し替え、API従量課金ゼロ ＆ 超高速実行を実現。

03

認証セッションのキャッシュ（auth.setup.ts）

テストごとに毎回ログイン画面を操作する無駄を省き、あらかじめ保存したセッション状態を使い回すことで、テスト実行時間を大幅短縮。

04

Claude Code流 TDD ＆ 自己修復ループ（Self-Correction）

テスト実行でエラーが発生した場合、AIがターミナルログを自己解析し、コード修正〜再テストまで自動で合格するまで自律ループします。

3

段階的な進め方（スモールスタート）

まずはここから着手！
Phase 1 (最優先)

コア機能の自動検証

  • Playwright環境セットアップ
  • 講師・生徒のログイン認証テスト
  • 2画面リアルタイム同期テスト
Phase 2

主要業務フロー

  • 畑区画キャンバス（配置・編集）
  • 栽培日誌の作成・編集・削除
  • Gemini AI相談（モック検証）
Phase 3

異常系 ＆ CI自動化

  • オフライン（電波切れ）テスト
  • GitHub Actionsでのプルリク自動実行
  • テストレポートの自動出力
