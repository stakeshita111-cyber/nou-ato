ひと目でわかる！テスト専門用語集

計画書に出てくる専門用語を、初心者にもわかりやすい日常の言葉で解説した用語集です。

🏷️ テストの優先度（Priority）
  • P0 最優先（必須・Blocker）: ここが動かないとアプリとして成り立たない、本番公開を直ちに止めるレベルの重要項目（例: ログイン、2画面同期、ビルド成功）。
  • P1 重要（Important）: 日常の業務に直結する重要機能（例: 観察記録の編集・削除、タスクの巻き戻し、検索）。
  • P2 通常（Normal）: 補助的な機能や、使用頻度の低い便利機能（例: 高度な絞り込み、細かなAI語調調整）。
🧪 テストの階層（ピラミッド）
  • 単体テスト (Unit Test): 計算式やプログラムの小さな部品単位が正しく動くかのピンポイント検査（例: 畑区画の高さ計算）。
  • 結合テスト (Integration Test): 画面のボタンを押した時に、データベースや裏側の仕組みが正しく連携して動くかの検査。
  • E2Eテスト (End-to-End): ユーザーが実際にブラウザを開いて操作する「最初から最後までの通しテスト」（例: 先生がPCで野菜を植えて、生徒のスマホ画面が自動で切り替わるまで）。
🛡️ セキュリティと権限の用語
  • RBAC (ロール制御): 先生（講師）と生徒（受講生）で、使える画面やボタンをきっちり分ける仕組み。
  • RLS (Row Level Security): データベース側にかける「他人のデータを見せない・触らせない」絶対の電子錠。
  • XSS (クロスサイトスクリプティング): メモ欄などに悪意あるプログラムコードを書き込んで乗っ取りを狙うサイバー攻撃の手法。
  • サニタイズ (無害化): 入力された危険な文字（<script> など）を、安全なただの文字に自動変換すること。
⚡ 通信と動作の用語
  • BroadcastChannel: 同じブラウザの別タブ同士が、インターネットを経由せず 0.01秒で直接おしゃべりする超高速通信。
  • レースコンディション (競合): 2人が同時に同じデータを触ったり、ボタンを連打した時にデータが壊れてしまう不具合。
  • Empty State (空状態): 新入生が初めてログインした時など、まだデータが1件も入っていない初期画面のこと。
  • DoD (完了定義): 「この条件を100%クリアしたら本番公開してOK」という事前の合格約束ライン。
🛡️

品質保証原則：テスト結果の完全保全と不具合即時起票ポリシー

❌ 勝手な合格化・修正の禁止

テスト失敗時に、AIやスクリプトが期待結果を緩めたり、勝手にコードを書き換えてPASS扱いにする行為を厳禁します。

📝 証跡の完全保存とTSV記録

失敗時はコンソールログ・画面録画・スタックトレースを保存し、test/test.tsv の実際結果欄へ正確に記録します。

🔍 開発者・QAへの明確な報告

不具合原因（再現手順・差分）を明記したバグレポートを作成し、人為レビュー・正式修正を経てから再テストを実施します。
